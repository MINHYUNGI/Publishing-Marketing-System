# SCM 실판매 Supabase 통합 검토 보고서

작성일: 2026-08-21  
상태: 라이브 Supabase Migration 및 최초 적재·자동 대조 완료

## 적용 원칙

- `Y:\출판사업본부\05. 영업 실적`은 읽기 전용으로 사용했습니다.
- 기존 SCM 프로그램, 기존 대시보드, `실판매_통합원장.xlsx`는 수정하거나 삭제하지 않았습니다.
- 기존 실판매 대시보드 HTML/CSS/JavaScript를 `ui/scm-dashboard.html`로 그대로 이식하고 데이터 로딩부만 Supabase API로 교체했습니다.
- 별도 Supabase 프로젝트를 만들지 않으며, 현재 프로젝트 `ttqeovahaitfkalbfucl`에 적용할 Migration만 작성했습니다.
- 사용자 승인 후 라이브 Migration과 최초 적재를 실행했으며 각 단계에서 원본과 자동 대조했습니다.

## 구현 내용

1. `SCM거래처`, `SCM제품매핑`, `SCM일별실판매`, `SCM동기화이력`, `SCM동기화거래처결과` 및 원자적 확정을 위한 내부 스테이징 테이블을 정의했습니다.
2. PK/FK/UNIQUE/조회 인덱스/RLS/권한과 `SCM동기화확정()` 함수를 포함했습니다.
3. 원장 파서와 사전검증, 신규/수정/동일/미매칭 분류, 전체 날짜 범위 교체 방식의 멱등 동기화를 구현했습니다.
4. 데이터 관리 화면에 SCM 사전검증·동기화·최근 결과·거래처별 결과 영역을 추가했습니다.
5. 좌측 메뉴에 `실판매 관리`를 추가하고 기존 대시보드 UI를 iframe 내부에 보존했습니다.
6. 출간 후 성과에 SCM 전체 및 교보/영풍/YES24/알라딘 일별 판매를 ERP와 동일 날짜축으로 연결했습니다.
7. YES24 원본 113개를 직접 분석하여 `YES24구매자스냅샷`과 `YES24구매자분포`를 추가하고, 향후 SCM 동기화 때 자동 적재하도록 연결했습니다.

## YES24 원본 직접 분석

- 파일명 확장자는 `.xls`이지만 실제 내부 형식은 XLSX입니다.
- 기존 수집 코드가 조회 시작일과 종료일을 같은 날짜로 지정하므로 `기준일=기간시작일=기간종료일`인 하루 단위 자료입니다.
- 원본 Grain은 `기준일 × 성인/아동 계정 × ISBN13`입니다.
- 성별과 연령은 각각 독립된 주변분포이며 성별×연령 교차 데이터는 원본에 없습니다.
- 성별 원본 구간: 남, 녀, 미가입
- 연령 원본 구간: 기타, 10대 이하, 20대 초/후, 30대 초/후, 40대 초/후, 50대 초/후, 60대 이상
- 지역 원본 구간: 서울, 경기, 충청, 경상, 전라, 강원, 제주
